## 一、快速开始

如果你只是想“先用起来”，最直接的方式是直接打开一个稳定的订阅转换前端，并按提示填入相关信息即可。

### 1. 直接使用前端

打开 [肥羊订阅转换前端](https://sub.v1.mk/)，输入你的订阅链接，选择生成类型（建议选择 `Clash`），然后点击转换即可。

[![pEq5VwF.png](https://s21.ax1x.com/2025/05/06/pEq5VwF.png)](https://imgse.com/i/pEq5VwF)

> 适用场景：刚接触订阅转换、需要快速生成 Clash 配置、希望短时间内上手使用。

------

## 二、为什么要做订阅转换

订阅转换的核心价值，在于把不同来源的节点订阅统一整理成一个更加适合自己客户端使用的配置文件。

常见用途包括：

- 把不同机场的订阅统一到一个客户端中
- 将节点按地区、类型、延迟进行筛选
- 自动生成 Clash、Shadowrocket、V2ray 等兼容格式
- 使用远程规则和策略组实现更稳定的分流
- 提高长期维护时的可读性和可管理性

------

## 四、订阅转换的关键参数说明

以下以 [肥羊订阅转换前端](https://sub.v1.mk/) 为例，讲解常用字段。

### 1. 订阅链接

订阅链接指的是需要转换的原始订阅地址。它必须直接包含节点信息，不支持把已经转换过的结果再次“套娃”放进去，否则识别不到。

注意：

- 可放多个订阅
- 每行一个链接，或者用 `|` 分隔
- 建议保留原始链接，后续更新时更容易排查问题

### 2. 生成类型

这里通常选择 `clash`，因为 Clash 系客户端和 Shadowrocket 兼容性较好，适用范围大。

常见类型：

- `clash`
  - 适用于 Clash 系客户端
  - 兼容大部分常见代理软件
- `mixed`
  - 混合订阅：将不同协议节点打包成纯节点信息并做 Base64 处理
  - 适用于 V2Ray 系和 Shadowrocket 等客户端

#### Clash 系客户端示例

- Windows
  - Clash for Windows
- Android
  - Clash for Android
- iOS
  - Stash
  - Choc
- macOS
  - ClashX Pro
- Linux
  - OpenWrt / OpenClash
- 其他
  - ShellClash

> 选择时请根据你自己的客户端进行匹配，否则转换结果可能无法正常使用。

### 3. 后端地址

一般情况下，用户只能选择前端提供的后端地址，不能随意自定义。若长期使用，建议优先选择稳定性较好的后端服务。

通常建议：

- 稳定性 > 功能多样性
- 兼容性 > 过度定制
- 选择长期维护、更新频率合理的后端

### 4. 短链选择

转换后的订阅地址通常会比较长，不方便复制和分享，因此有时可以启用短链接。

建议：

- 如果你自己搭建了环境，推荐使用 [YOURLS](https://github.com/YOURLS/YOURLS)
- 如果你只需要日常使用，短链功能可以提高复制体验

### 5. 远程配置

#### 分流配置

你可以选择系统内置的规则，也可以直接填入远程规则地址。注意：必须使用直链地址，不能使用页面跳转链接。

自用 Clash 分流规则直链：

- https://raw.githubusercontent.com/digitcloud/clashrule/main/General_Multi_Country_Enhanced_Media.ini

#### 自定义策略组

常见策略组模式：

- 延迟最低：按延迟检测选择最优节点
- 故障转移：优先使用第一个节点，失败后切换下一节点
- 手动选择：按需选节
- 负载均衡：多个节点轮询使用

> 这部分更适合长期使用时的“规则优化”，能够让你的节点分流更稳定和合理。

### 6. 节点筛选规则

筛选规则通常用于控制哪些节点被保留。常见示例：

- 选择全部节点：
  - `.*`
- 选择全部新加坡节点：
  - `(新加坡|坡|狮城|SG|Singapore)`

> 建议在长期使用中逐步整理自己的筛选规则，避免节点列表过于混乱。

### 7. 分流规则

分流规则有两种写法：

- 直接写入规则
- 引用现成规则库

推荐优先采用引用方式，维护更方便。

#### 常见规则库

- ACL4SSR：
  - https://github.com/ACL4SSR/ACL4SSR/tree/master/Clash
- blackmatrix7：
  - https://github.com/blackmatrix7/ios_rule_script/tree/master/rule/Clash

#### 排序原则

分流规则匹配通常是“从上到下”，一旦命中就停止继续往下匹配。因此建议遵循以下顺序：

`重要直连分流规则 > 去广告规则 > 小分流 > 国内外大分流 > 补充规则`

> 这是长期稳定使用时最容易忽略、但非常关键的一点。

## 五、高级功能与长期管理建议

### 1. 包含节点

用于筛选节点黑名单，仅保留符合规则的节点。

常见规则：

- 只用香港节点：
  - `HK|香港|Hong Kong`

### 2. 排除节点

用于筛选节点白名单或排除不需要的节点。

常见规则：

- 去除官网信息节点和流量信息节点：
  - `官网|流量`

### 3. 节点命名

可以根据规则重命名节点，便于长期管理和识别。

### 4. 更新间隔

建议根据你的订阅更新频率设置合理间隔，避免过于频繁导致客户端不稳定。

### 5. 订阅命名

订阅名称会显示在客户端界面中，建议命名简洁、清晰、可区分。

### 6. 更多选项

常见开关：

- Emoji：默认开启，界面更友好
- 启动 UDP：推荐开启，适合打游戏、打电话等场景
- 启动 TFO：推荐开启，提升传输效率

## 六、长期使用建议

如果你要长期使用订阅转换工具，建议遵循下面的思路：

1. 优先选择稳定且长期维护的前端
2. 保留原始订阅链接，便于后续排查问题
3. 把规则文件单独管理，避免每次都重写配置
4. 定期检查规则更新，避免落后或失效
5. 建立自己的筛选规则和策略组模板
6. 尽量不要一味追求“复杂配置”，长期使用中稳定优先

> 对于长期维护而言，稳定和可迁移性往往比“功能强大”更重要。

------

## 七、注意事项

- 订阅链接必须是原始节点信息，不要放已经转换过的嵌套结果
- 规则链接必须为直链，不支持普通网页跳转
- 不同客户端对 Clash 配置的兼容性不完全一致，选择前请确认
- 如果一个订阅长期无法使用，优先检查链接有效性和后端是否正常
- 不建议为了“炫技”配置过多复杂规则，长期使用时应以稳定为主

------
